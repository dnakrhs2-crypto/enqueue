## 결정 (gom 승인 — 바꾸지 말 것)

### A. 합방 인원·연결
1. **방 최대 3명.** 방장은 항상 LiveMix. 나머지 최대 2자리는 LiveMix 또는 웹. **웹은 방에 최대 1명.**
   가능한 조합: LiveMix+LiveMix(지금), LiveMix+웹, LiveMix 2+웹, LiveMix 3.
2. **방장 PC가 서버.** 소리는 우리 서버(유튜브다운.com)를 지나가지 않는다. 우리 서버는 방 코드·주소 교환·연결 정보(시그널링)만.
3. **방장 중심 별 모양.** 각 참가자는 방장과만 연결한다. 방장이 각 참가자에게 다른 사람 소리를 넘긴다(참가자는 지금처럼 포트를
   열 필요 없음). LiveMix 참가자에게는 사람별로(발화자 구분) 넘겨 그 사람 OBS에서도 사람별 소스가 되게 한다.
4. **OBS 사람별 소스(LiveMix 사용자):** 'LiveMix'(내 소리) + **'합방 상대 1' / '합방 상대 2'** 두 자리. 자리에 닉네임 표시,
   나간 사람 자리는 무음으로 유지하고 남은 사람의 자리 번호는 바뀌지 않는다. 웹 사용자도 한 자리를 쓴다.
   기존 'LiveMix 합방 상대' 소스(링 `Local\LiveMix.ObsAudio.v1.Peer`)를 이미 장면에 넣은 사용자는 그대로 '자리 1'로 동작해야 한다.
5. 상대 소리의 헤드폰 경로(마스터/직접 출력/OBS에서 듣기)·상대 음량·상대 목소리 ON/OFF는 지금 합방 창 설정을 모든 상대에 함께 적용.
6. 지금의 2명 합방(0.15.x 홀 펀칭·UPnP·방 샘플레이트 48/44.1·버퍼 유지)은 그대로 동작해야 한다(회귀 금지).

### B. 웹 참여
7. 웹 사용자는 LiveMix 없이 브라우저로 참여한다. **PC 크롬·엣지 우선.** 폰 브라우저도 막지 않는다(동작은 gom이 버즈로 시험).
8. **웹 사용자 말 = 모노, 듣기 = 스테레오.** 웹 사용자에게는 방장이 섞은 '자기 빼고 전부'(방장 + 다른 LiveMix 참가자)의 스테레오
   한 줄을 보낸다. 웹 사용자 모노 목소리는 다른 사람에게 가운데(좌우 같게)로 들린다.
9. **전송 = WebRTC 데이터 채널(순서 무시·재전송 없음) + 무압축 PCM.** 브라우저 기본 통화 기능(오디오 트랙·Opus)은 쓰지 않는다
   (크롬·엣지가 스테레오를 모노로 받는 문제). 방장 LiveMix 쪽 라이브러리 = libdatachannel(MPL-2.0, 미디어 기능 없이).
10. **웹 페이지는 곰튀김.com(LiveMix 공식 사이트, 저장소 `site/`, GitHub Pages HTTPS)의 `/livemix/join/`** 에 둔다
    (브라우저 마이크는 보안 주소에서만 켜짐, gom 원문 15). 초대 링크 = `https://곰튀김.com/livemix/join/#…`(QR은 퓨니코드
    `xn--jb0byyo90f.com`). 시그널링 API는 유튜브다운.com 방 서버 그대로 — 페이지가 뒤에서 다른 출처로 부르므로 CORS 허용(곰튀김.com
    출처만). GitHub Pages는 응답 헤더를 못 정하므로 교차 출처 격리(SharedArrayBuffer)는 기대하지 않는다. 소리는 방장 PC로 직접.
11. **들어오기 = QR·주소 + 방장 수락.** 방장 LiveMix 합방 창에 웹 초대 QR과 주소(복사)를 보여 준다. 웹 사용자가 열어 닉네임 →
    마이크 허용 → 들어가기 → 방장 합방 창에 들어오기 요청(닉네임)과 [수락]/[거절] → 수락하면 연결. 방장은 연결된 웹 사용자를
    [내보내기] 할 수 있다. 초대 주소에는 4자리 방 코드와 별개인 긴 토큰을 넣고, 방장이 초대 주소를 새로 만들면 옛 주소는 무효.
    (LiveMix 참가자는 지금처럼 방 코드로 들어온다 — 수락 단계 없음.)
12. **헤드폰 필수**(에코 제거·잡음 제거·자동 음량은 끈다). 웹 페이지에 헤드폰 안내 한 줄.
13. 웹 지연·끊김은 실측해서 보고한다(설계 추정 편도 40~130ms, 실측 아님).
13-1. **웹 '상대방 음량'(gom 원문 18).** 웹 사용자가 듣는 상대방 소리(방장이 섞어 보내는 스테레오 한 줄)의 음량을 웹 페이지
    '연결됨' 화면의 슬라이더로 직접 조절한다. LiveMix 합방 창과 같은 이름·범위: `상대방 음량` + %, 0~100%, 기본 100%, 그 기기에서
    다음에 들어와도 기억. 웹 사용자 쪽 재생에만 적용하고 보내는 소리·다른 사람이 듣는 소리는 바꾸지 않는다. 위치는 비교 시안
    `mock\webvol.png` B안(사람 목록 칸 아래, gom DM post obqsbsfdo7gsxy6jkzjceh9izo — 답 전 추천대로).

### C. 녹음
14. **마스터 카드에 [녹음] 버튼.** 누르면 **녹음 창**: 형식 WAV / MP3, MP3는 128 / 256 / 320kbps 중 하나, 저장 위치 →
    [녹음] 누르면 창이 닫히고 녹음 시작. **멈추려면 녹음 창을 다시 열어 [녹음 중지]**(실수로 멈추지 않게 — gom 원문 10).
15. **WAV = LiveMix 장치 샘플레이트 그대로, 24비트 PCM.** **MP3 = 윈도우 내장 Media Foundation MP3 인코더**
    (CLSID_MP3ACMCodecWrapper, 입력 16비트 PCM, 32/44.1/48kHz) — 장치가 그 밖(예: 96kHz)이면 MP3만 48kHz로 바꿔 저장.
    JUCE의 `LAMEEncoderAudioFormat`(외부 lame.exe 필요)은 쓰지 않는다.
16. **녹음 파일(gom 원문 16):** 합방이 없으면 내 마스터(OBS 'LiveMix'와 같은 소리) 파일 하나. **합방 중 녹음이면 녹음 한 번에
    폴더 하나(날짜·시각 이름) 안에 A = 내 소리, B·C = 합방 상대 1·2(헤드폰 음량·ON/OFF 적용 전 = OBS '합방 상대 1·2'와 같은
    소리), D = 전체 합본(A+B+C)** — 2명이면 A·B·D. 모든 파일은 같은 샘플에서 시작해 길이가 같다(편집 프로그램에서 줄이 맞음).
    상대 자리가 비어 있는 동안 그 파일은 무음, 녹음 중 누가 들어오거나 나가도 파일 묶음은 그대로 이어진다(녹음 시작 때 합방이었으면
    사람별 파일을 만든다 — 녹음 중 합방이 시작되면 그때부터는 클로드 기본값: 녹음을 새로 시작하기 전까지 파일 하나 그대로).
    (10/26 R0 검토 뒤 클로드 확정: 합방 중 시작이면 넷을 모두 열고 녹음 내내 아무도 없던 자리 파일은 멈출 때 지운다 — 녹음 중
    들어온 사람도 자기 파일, 2명이면 결과 A·B·D. 녹음 중 합방이 시작된 파일 하나에도 상대 소리를 합친다. 자리 파일은 모두
    스테레오(웹은 좌우 같은 소리) — 계약 §7.) 형식·비트레이트는 녹음 창에서 고른 그대로 모든 파일에 적용. 디스크: WAV 48k·24비트 스테레오 4개
    약 4.1GB/시간, MP3 320kbps 4개 약 0.6GB/시간(산술). 4개 동시 녹음 CPU는 구현 뒤 이 PC에서 실측해 보고.
17. 클로드 기본값(gom 변경 가능): 녹음 중엔 마스터의 녹음 버튼이 빨간색 + 경과 시간 / 파일 이름 = 날짜·시각
    (`LiveMix_2026-10-26_14-05-33.wav`) / 기본 저장 위치 = `문서\LiveMix 녹음` / WAV가 4GB 직전이면 다음 파일(`…_2.wav`)로
    끊김 없이 이어서 / 녹음 중 프로그램이 갑자기 꺼져도 그때까지의 녹음은 열리는 파일로 남게 / 형식·비트레이트·저장 위치는 기억.
18. 녹음 중 장치 샘플레이트가 바뀌면 그 파일을 닫고 새 파일로 이어서 녹음(WAV는 파일 하나에 샘플레이트가 하나). 앱을 끄면 파일을
    마무리하고 끈다.
