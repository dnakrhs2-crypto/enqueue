# 최근 프로젝트 다시 열기 — 결정·구현 메모

- 범위: Enqueue의 시작 시 최근 프로젝트 1개 재열기와 이 PC의 정책 메뉴.
- AppSettings의 lastSessionProject는 절대 경로 문자열; 빈 세션은 기존 파일 키 관례대로 키를 제거한다.
- lastProjectFile(파일 선택창 경로), 업데이트용 reopenProjectAfterUpdate는 기존 용도를 유지한다.
- reopenLastProjectPolicy는 ask(기본) / always / never; 모르는 값은 ask로 읽는다.
- 열기·저장/다른 이름 저장 성공, 새 프로젝트 전환(빈 값), MainComponent 종료 때 세션 경로를 즉시 저장한다.
- ReopenLastProject.h의 순수 판단 함수에 시작 경로·정책·파일 존재·현재 프로젝트 상태를 전달한다.
- 명령줄 열기 성공 / 업데이트 재열기 성공 / 안전 모드 / never / 빈 경로 / 없는 파일 / 이미 열림은 재열기 없음.
- 없는 세션 파일의 경로는 정책이나 시작 경로에 관계없이 비운다.
- always는 바로 openProjectFile(file, true), ask는 비동기 JUCE AlertWindow.
- 제목: 최근 프로젝트 다시 열기; 본문: '<프로젝트 이름>'을(를) 다시 여시겠습니까? + 다음 줄 전체 경로.
- 버튼: 열기(Return) / 항상 열기(always 저장 후 열기) / 새 프로젝트(Esc, 세션 경로 비우기).
- 기존 ShortcutRouter 창 등록과 JUCE 모달 상태로 일반 키·MIDI 억제 및 패닉을 유지한다.
- 확인 중 다른 프로젝트가 열리거나 편집되면 뒤늦은 응답으로 덮어쓰지 않는다.
- 설정의 글씨·화면 크기 바로 아래 시작할 때 최근 프로젝트 (이 PC): 묻기 / 항상 열기 / 열지 않음.
- 세 명령은 uiScale과 같은 카탈로그 범주·범위, 기본 키 없음, 저장값 체크, 쇼 모드 비활성.
- 테스트: 설정 왕복·기본값·미지 값, 판단 조합표, 실제 열기·저장·새 프로젝트·종료, 모달·메뉴·자동 시작 게이트.
- 저장 선택창의 실제 쓰기 경로를 writeProjectToFile로 분리해 다른 이름 저장 성공/실패를 검증한다.
- 다른 경로의 프로젝트 열기가 성공하면 자동 시작 전에 재열기 확인창을 닫고 창 수명으로 대기 콜백을 무효화해 키·MIDI 입력을 복구한다.
- 정책 저장 실패는 원래 값·저장 대기 상태로 복원하고 알린다. 세션 경로 저장 실패는 프로젝트 파일 저장과 구분하고 다음 변경 때 재시도하며, 종료 시에는 조용히 시도한다.
- 억제 상태는 std::optional<juce::String> notifiedFailedSession: 마지막으로 안내한 실패의 desired(빈 경로 포함)와 같을 때만 억제하고, 다르면 안내 후 기억을 갱신한다.
- 세션·정책·프로젝트·입력 설정·종료 등 앱이 아는 모든 saveNow 성공은 공통 콜백에서 기억을 비운다. 관찰할 수 없는 지연 자동 저장은 관찰하지 않으며 PropertiesFile 옵션·타이머는 바꾸지 않는다.
- 디스크와 desired의 새 불일치는 새 desired 저장 실패 때만 생긴다. 이 값은 마지막 안내 값과 다르므로 반드시 안내되고, 이미 안내한 동일 값의 반복 실패만 억제된다.
- 반복 실패 사이 타이머가 그 값을 저장했다면 디스크는 이미 desired와 같아 위험이 없다. 이후 다른 desired 저장이 실패하면 값이 달라 다시 안내된다.
