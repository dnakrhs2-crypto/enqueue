# LiveMix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lightweight live mic VST3 host for broadcast: ASIO in → per-channel VST3 chain → mic ON/OFF → master / direct outs, FX channels with pre/post sends, sessions, tray operation, WebDAV backup.

**Architecture:** A second app target in the Enqueue repo (`livemix/`), linking `GoCueCore` for VST3 hosting (`PluginHost`, `PluginChain`, `PluginWindows`), settings, updater and the verified file write. New code: `MixSession` (model + JSON), `MixEngine` (graph on one ASIO device, offline-renderable for tests), the card UI, tray, WebDAV backup.

**Tech Stack:** JUCE 8 (C++17, MSVC), Inno Setup, WinSparkle, headless Chrome mocks in `scratchpad/micrack`.

**Spec:** `docs/superpowers/specs/2026-09-04-livemix-design.md`

## Global Constraints

- ASIO only; the device list shows ASIO devices only; every input and output of the device is opened.
- No channel gain / fader: channels are unity. Mic ON/OFF is a 5 ms ramp and cuts the sends too.
- UI words: 마이크 채널 / 마이크 ON·OFF / VST3 체인 / 이펙터 / FX 채널 / 마스터 / 출력 / 세션 / 온라인 백업 (never 뮤트·게인·AUX·센드).
- Colours and fonts through one palette (`livemix/src/ui/LiveMixPalette.h`), never hard-coded in components.
- Every task ends with the full test suite green (`build/vs2022/tests/EnqueueTests_artefacts/Release/EnqueueTests.exe`) and a Codex read-only review before the release task.
