**LiveMix 0.17.7 PLC FIX1: 복구 중 재손실의 잔류 음성 제거 (2026-10-29)**

이 문서는 FIX1 당시의 기록이다. 30ms 재시작 조건의 회귀 수정과 최신 시험·Probe 정보는 [FIX2 OUT](livemix-0177-plc-fix2-OUT.md)에 있다.

복구가 끊길 때마다 합성음을 새 원음으로 저장하고 감쇠를 다시 시작하던 원인을 수정했다. `CollabPlc`의 원음 기록에는 복구 겹침 전의 실제 입력만 저장한다. 충분한 실제 입력이 연속해서 들어오기 전의 재손실은 같은 `frozen` 파형, 위상, 감쇠 시간을 이어 쓴다.

브랜치 `livemix-0177-plc`, HEAD `dae954ba228849d0824474c0e5a6f8e74096a68a`. 커밋하지 않았다. `plc_soak_done.flag`가 12:09:48 KST에 생성됐고 60초 확인 루프가 12:10:01에 확인했다. 이번 전후 빌드·시험은 모두 그 뒤 `rb.py`를 통해 roomc에서 실행했다. 수정 전 재현 빌드는 12:11:45에 시작했다.

**새 손실 구간을 시작하는 기준**

복구 겹침이 끝나고, `correlationFrames + maxPitch`만큼의 연속된 실제 입력이 쌓여야 한다. 48kHz에서는 720+720=1,440프레임, 30ms다. 44.1kHz에서는 반올림에 따라 662+662=1,324프레임, 약 30.023ms다. 현재 피치 탐색이 최근 15ms와 최대 15ms 이전을 비교하므로, 이 길이가 있어야 탐색 창 전체를 새 실제 입력으로 채울 수 있다. 손실이 끼면 연속 기록 길이를 다시 센다. 실제 무음도 유효한 실제 입력이다.

이 기준은 다음 손실에 쓸 원음 기록을 교체하는 시점만 정한다. 실제 소리를 기다렸다 출력하지 않는다. 기존 한 주기 복구 겹침이 끝나면 즉시 실제 입력 그대로 출력한다. 이전 손실 구간의 시계는 짧은 정상 패킷과 겹침 이후의 실제 출력 시간을 포함해서 계속 흐른다. 감쇠 수치는 첫 10ms 원래 크기, 이후 10ms당 20% 선형 감소, 60ms부터 정확한 0으로 유지했다.

**수정 전 실패, 수정 후 통과**

137Hz 기본음에 2·3·5배음을 더한 스테레오 신호 100ms 뒤 실제 입력을 무음으로 바꾸고, 아래 손실/정상 패턴을 1초 반복했다. 진폭은 1·2·3·5배음 각각 0.27/0.12/0.08/0.04, R=0.63L. 표는 L채널 정규화 PCM 수치이며, 시각은 최초 손실부터 센다. 44.1kHz의 구간 길이는 가장 가까운 프레임으로 반올림한다.

| 장치율 | 손실/정상(ms) | 900~1,000ms RMS 전 → 후 | 60~1,000ms 최대 절댓값 전 → 후 |
|---|---|---:|---:|
| 48kHz | 5/2.5 | 0.073800938 → 0 | 0.338174164 → 0 |
| 48kHz | 2.5/2.5 | 0.040468609 → 0 | 0.305669516 → 0 |
| 48kHz | 5/5 | 0.002377220 → 0 | 0.317108095 → 0 |
| 48kHz | 2.5/10 | 0 → 0 | 0.043983541 → 0 |
| 44.1kHz | 5/2.5 | 0.005813833 → 0 | 0.293369144 → 0 |
| 44.1kHz | 2.5/2.5 | 0.044487846 → 0 | 0.367201656 → 0 |
| 44.1kHz | 5/5 | 0.001753067 → 0 | 0.217850283 → 0 |
| 44.1kHz | 2.5/10 | 0 → 0 | 0.044534888 → 0 |

수정 전 동일 검사 38개 중 19개가 실패했다. 수정 후 38개가 모두 통과했고, 8개 반복 조합 모두 60~1,000ms 출력은 샘플마다 정확한 0이었다. `2.5/10`은 복구 겹침이 이미 끝났지만 새 실제 기록 30ms가 아직 없는 경우도 검사한다.

5ms 손실 조합에서는 이음 보정이 끝난 손실 구간의 출력과, 같은 초기 원음을 끊김 없이 계속 숨긴 기준 출력을 비교했다. 고정 원음·위상·감쇠 오차가 48kHz에서 최대 0.300168186 → 0, 44.1kHz에서 최대 0.214585304 → 0이었다. 비교는 각 손실의 4ms 이후에 하므로 2.5ms 손실 조합에는 이 수치를 적용하지 않는다. 전체 반복 구간의 최대 인접 샘플 변화량은 48kHz 0.016917706, 44.1kHz 0.018415730으로 전후 같았다.

새 70Hz 배음 음성을 연속 30ms 받은 뒤 다음 손실을 만들었을 때, 그 30ms 원음만 받은 새 PLC와 전체 스테레오 숨김 출력이 비트 단위로 일치했다. 수정 전에는 불일치했다. 새 음성의 첫 10ms 숨김 RMS는 0.242081로 정상 크기이고, 실제 무음 30ms 뒤의 다음 손실은 정확히 0이었다. 기존 최대 15ms 겹침 이후에는 30ms 기준을 기다리지 않고 실제 샘플 그대로 통과하는 검사도 통과했다.

수정 전 수치는 독립 모델이 아니라 보존한 실제 `CollabPlc.cpp`를 별도 C++ 실행 파일로 빌드한 결과다. 일반 제품 시험은 수정된 `LiveMixCore`를 링크한다.
